# 流畅度与性能验证

v0.2.3 beta 保留高清壁纸、高清唱片封面和现有玻璃外观，重点减少界面线程中的重复计算与突发工作。

## 渲染与图片处理

- Wallpaper Engine 的 `QVideoSink` 在独立事件线程接收帧，避开 Qt capture session 到 sink 的逐帧 GUI 排队。该线程只更新 `latest_video_frame.h` 的最新源帧缓冲，不映射图像或访问控件。暂停和停止先禁用邮箱、停止捕获并排空接帧线程旧事件；删除 sink 前移回 GUI，解除 capture session 绑定。
- Wallpaper Engine 捕获对可直接读取的普通 32 位 RGB 帧使用后台转换：映射并复制成独立 `QImage`，避开 Qt 通用转换中的额外纹理上传与读回。格式、色彩及方向检查不满足条件的 YUV、HDR、硬件纹理等帧仍在界面线程使用 Qt 转换；后台直接转换失败返回空图，不在工作线程调用 Qt／QRhi 的回退路径。
- 捕获转换最多保留一个在途任务、一个最新源帧和一个待显示结果。完成回调存储当前代次的图像，并原子取出下一张兼容 RGB 帧开始唯一的新任务，减少等待；不兼容帧留给 GUI 回退。只有显示帧截止时间才发布图像，不在完成时额外插入重绘。暂停、换源、停止和改变渲染尺寸会清空结果并使旧代次失效；旧任务结束前仍保留忙碌状态，快速恢复也不会排入第二个任务。同尺寸的窗口守护不清帧。
- WE 渲染请求与 Surface 统一按 `ceil(逻辑尺寸 × DPR)` 计算物理尺寸；精确匹配的捕获图像先直接共享，再考虑其他图像的比例裁剪。避免非整数 DPI 的半像素比例差导致整帧缩放，导入图片和视频继续按原有比例居中裁剪。
- `AeroSurface` 共享原始分辨率背景纹理；动态玻璃模糊最多有一个正在运行的后台任务和一个待更新状态，独立预算最高为 60 Hz，低刷新率屏幕则跟随屏幕。清晰壁纸的呈现预算保持独立，不降低源图分辨率。首次显示、换主题和尺寸变化立即生成对应模糊，异步完成结果按代次和尺寸校验。
- 毛玻璃结果优先随下一次源画面一起显示，避免每帧的后台完成回调再触发一遍透明面板合成；源画面停止时，32 ms 定时回调补上最后一次重绘。只采样清晰背景的歌曲列表不参加模糊完成后的补绘。
- `liquid_image_blur.h` 保留原有两轮水平／垂直盒式模糊及边缘延伸，按连续像素和小块访问内存。随机透明像素、窄图、非整块宽度及带行填充的图像验证逐像素一致。
- `CoverImages` 用两个线程解码、裁剪与缩放封面。高清请求保留原图尺寸，并优先于缩略图。界面线程创建 `QPixmap/QIcon` 并更新控件。
- 解码器最多容纳 128 个在途及排队请求；单个编码文件上限 16 MiB，待解码编码文件合计上限 64 MiB，另有最多两个在执行的文件。原图像素上限为 4000 万。满队列会拒绝或退让缩略图，调用方移除请求标记以允许后续重试。
- 歌曲封面按封面键查找对应行，并合并到一次定时更新。音乐库追加歌曲或更新同一行的元数据时复用原有条目；新增重复歌曲继承同键已加载封面。切换屏幕 DPI 时清理旧密度图标并拒绝其延迟回调。
- 动画、壁纸呈现、滚动与卡片晃动使用按纳秒累计的帧截止时间，跟随当前屏幕的 30–360 Hz 刷新率预算。GUI 迟到超过半帧时从当前时间安排下一帧，给输入处理留出空间，不在恢复时紧接着补画；正常帧保留分数间隔。
- 滚轮改变一个持续收敛的目标；滚动与卡片晃动共用一次更新，停止滚动后才启动短暂的弹性恢复。触控板使用系统像素与惯性事件。仅更新可见区域，停止后关闭动画定时器，拖滚动条和键盘定位优先于旧惯性目标。
- 歌曲文字按实际 DPI 缓存为透明像素，每项保留两个最近使用的像素密度，避免毛玻璃内容抓取与高清视口交替绘制时互相淘汰；总条目缓存仍有上限。文字、字体、列宽或颜色变化时重建，卡片变形不再每帧重新排字。高清背景在世界坐标中采样，玻璃轮廓、封面、文字及高光继续随卡片变形，避免重复剪切整幅背景纹理。
- Wallpaper Engine 的真实场景／网页源限帧来自它自己的全局设置。主题页只读显示该设置并提供打开 WE 的入口，不更改桌面配置。当前 Qt 6.11.2 FFmpeg 捕获后端还有 `MaxScreenCaptureFrameRate = 60` 上限；WE 源设置与界面定时器预算为 165 Hz，也不能使它捕获 165 FPS。[Qt 捕获限帧实现](https://raw.githubusercontent.com/qt/qtmultimedia/v6.11.2/src/plugins/multimedia/ffmpeg/qffmpegsurfacecapturegrabber_p.h) 视频壁纸保留素材原帧率。

## 计时范围

`BackgroundSurfaceTest` 输出三项计时：快速输入时的前台绘制耗时、最后一个模糊结果追赶耗时、按约 16 ms 间隔输入时的前台中位数和 95 分位数。后台线程的 CPU 计算不包含在前台耗时中；快速循环中的部分帧会共享先前完成的模糊。

这些计时用于定位开销，不能换算成软件整体 FPS。应在构建任务结束后独立运行，并检查最后一帧的模糊确实收敛。真正的体验验证需要同时播放动态壁纸、滚动大歌单、加载封面、展开 Dock 和触发流星，观察慢帧与输入响应。

2026-10-08 在本机 Release 构建中对原核和新核交错计时，典型玻璃内容样本的四次模糊处理结果如下。尺寸是送入模糊核的图像像素，计时不含控件捕获、图像缩放、壁纸解码和屏幕呈现。

| 样本尺寸 | 原核中位数／95 分位 | 新核中位数／95 分位 |
| --- | --- | --- |
| 256 × 160 | 1.368／1.568 ms | 0.752／0.940 ms |
| 640 × 360 | 6.783／9.489 ms | 3.432／4.595 ms |

此次典型样本模糊计算耗时约减少 45–50%，随机图像验证逐像素一致。歌曲卡片缓存键改为结构化键，减少临时字符串构造；其独立绘制计时变化处于重复测试波动范围内，因此不据此宣称帧率提升。

2026-10-08 的隔离滚动对照使用 12043 行、4K 静态高清背景和 20 个滚轮刻度，屏幕为 165 Hz，实际像素密度为 DPR 2.25。输入由探针统一注入，排除真实鼠标事件干扰。修复后的卡片仍保留整体果冻变形和世界坐标中的玻璃反射；同步滚动与晃动、缓存文字像素，并将高清背景采样从不断变化的仿射变换中移出，得到以下歌曲列表视口绘制耗时。

| 测量 | 修复前中位数／95 分位 | 修复后中位数／95 分位 |
| --- | --- | --- |
| 歌曲列表视口绘制 | 49.46／64.30 ms | 11.87／13.12 ms |

这是视口处理一次绘制事件的耗时，不包含整个应用、源壁纸渲染和最终屏幕呈现，不能据此换算成整体 FPS。

实际 Wallpaper Engine 场景的 Windows Graphics Capture 对照使用 2565 × 1411 像素源画面，WE 源设置为 165 帧。此轮探针手动在界面线程同步取最新帧、转换并发布，以隔离通用 Qt 转换与直接 RGB 路径的差异；它没有使用新增的后台转换流水线。

| 同步手动探针指标 | Qt 通用转换 | 直接 RGB 转换 |
| --- | --- | --- |
| 单帧转换中位数／95 分位 | 25.77／31.92 ms | 12.10／17.48 ms |
| 探针发布图像的平均频率 | 33.18 帧／秒 | 50.44 帧／秒 |

发布频率是探针交付图像的次数，不代表不同源画面的数量或最终呈现帧率。第一轮真实后台转换探针在不绘制 UI 的 4 秒测试中发布约 43.35 帧／秒，GUI 线程 CPU 时间约 15.63 ms；旧同步 Qt 转换约 3015.63 ms。这说明转换工作已移出 GUI，不能代表整个应用 CPU 时间、不同源画面数量或最终显示帧率。该轮尚未包含后续接帧线程与物理尺寸共享修复。

最终组合探针使用实际 WE 场景、2565 × 1411 物理像素、DPR 2.25、165 Hz 屏幕、12043 行和同时展开的玻璃歌单面板及 Dock，统一注入 20 个滚轮刻度。构建与测试结束后单独运行，并退出另一份旧版播放器。两次生产流水线测量的列表绘制中位数约 7.94–8.09 ms，95 分位约 14.66–15.20 ms；背景绘制中位数约 3.16–3.29 ms。原画面与背景纹理在所有检查的绘制中共享，未发生整帧重复缩放。探针图像交付约 41–42 次／秒，接帧通知约 54 次／秒；通知和交付都不代表不同画面的数量或最终屏幕帧率。静止列表时交付约 46 次／秒。

组合结果仍未达到 165 Hz 所需的 6.06 ms 整帧预算，不能宣称高刷新率已达标。剩余主要开销是高 DPI 下的软件绘制与多层透明合成。一次额外的物理坐标绘制实验虽通过严格像素对照，但没有改善此场景的计时，最终版本未采用该实验。

60 Hz 每帧约 16.7 ms，120 Hz 每帧约 8.3 ms。定时器目标频率、前台绘制速度与屏幕实际呈现帧率是不同的指标；原始视频帧率、Wallpaper Engine 配置和硬件性能也会影响结果。
